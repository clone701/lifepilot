## 守るべき規約

このプロジェクト固有の決定事項。破ると設計が成立しなくなる。

1. **SK の先頭を日付にする**（`D#<date>#...`）。
   「今日の全データを1クエリ」が成立する根拠であり、最も守るべき規則
2. **日付は JST 基準**の `YYYY-MM-DD`。UTC を使わない
   （日本時間の午前9時前が前日扱いになる）
3. **GSI / LSI を作らない**。必要になったらキー設計自体を見直す
4. **Scan を使わない**。Query で設計できないパターンが出たらキー設計を見直す
5. **`pk` のユーザー識別子は Cognito JWT の `sub` から取得する。**
   リクエストボディ・クエリ・パスパラメータから受け取らない
6. **SK 文字列を直書きしない。** キービルダーモジュール経由でのみ組み立てる
7. **栄養値は書き込み時のスナップショット**として保存する。
   食品マスタを参照する設計にしない（マスタ編集で過去記録が変わるのを防ぐ）
8. **顧客管理 KMS キーを使わない**（$1/月/キー）。AWS 所有キーを使う

## 運用ルール

- **新しいエンティティを追加するときは、機能 Spec より先に
  `.kiro/specs/database/design.md` を更新する**
- 各機能 Spec の Data Models セクションは
  `#[[file:.kiro/specs/database/design.md]]` で参照するだけにし、構造を書き写さない
- 上記規約から外れる設計が必要になった場合は、実装せずまず相談する

# プロダクト定義

## 言語設定

**ドキュメント言語**: 日本語

- Spec（要件定義書、設計書、タスク）は全て日本語で記述する
- コード内のコメントは日本語で記述する
- 技術用語（変数名、関数名、クラス名等）は英語を使用する

## プロダクト概要

**LifePilot** は、食事・運動・体重・生活習慣をまとめて記録し、蓄積したデータをもとに
「今日何をすればよいか」を分かりやすく示す生活管理Webアプリ。

単なる食事管理アプリのクローンではなく、
「食事管理 + 運動管理 + 生活習慣管理 + 自分のデータ分析 + AIによる個人最適化」
を組み合わせたものを目指す。

## ターゲットユーザー

- **初期**: 開発者自身のみ（自分専用アプリ）
- **将来**: 知人など複数ユーザーへ拡張
- 利用デバイスはスマートフォン中心。PCでも使えるレスポンシブWebアプリとする

## 最優先の価値基準

**「機能として存在する」より「毎日面倒なく使える」を優先する。**

開発の優先順位は以下の通り。

1. 自分が毎日使える
2. 入力が簡単
3. データが蓄積される
4. 蓄積されたデータを可視化できる
5. AIによってデータを活用できる
6. 将来的に複数ユーザーへ拡張できる

## MVPスコープ

**未確定**（Spec化して確認を取ってから実装する）

現時点で MVP に含める方向で検討している機能。

- 食事記録（朝・昼・夜・間食）とカロリー / PFC の自動集計
- 目標値管理（1日の目標カロリー・PFC・体重目標）と残量表示
- 体重・体脂肪率の日次記録とグラフ表示（7 / 30 / 90日）
- 運動記録（簡易。種目と回数・時間程度）

## MVPに含めない機能

以下は MVP では実装しない。基礎機能（記録 → 集計 → 目標 → グラフ）の完成後に検討する。

- AI機能全般（自然言語による食事入力、食事提案、「今日どうすればいい？」）
- 画像からの食事推定
- 長期データ分析・傾向分析
- 睡眠 / 疲労感 / 水分 / カフェイン / 飲酒などの生活習慣記録
- 「いつもの食事」テンプレート（入力負荷が問題になった段階で優先度を上げる）
- 複数ユーザー向けの招待・共有機能

## 制約・前提

- **医療的な位置づけ**: 診断や治療を行うアプリにはしない。ユーザーが入力したデータに
  基づく生活上の提案に留める
- **AI推定値の扱い**: AIや画像認識が推定した値を無条件で確定しない。必ずユーザーが
  確認・修正できるUIを経てから保存する
- **データ分離**: 初期から `user_id` によるユーザー単位のデータ分離を前提に設計する。
  他ユーザーのデータは閲覧できない
- **入力UX**: スマートフォンでの操作数を最小化する。ボタンは大きく、入力項目は少なく、
  今日の状態が一目で分かること

## 用語定義

- **PFC**: タンパク質（Protein）・脂質（Fat）・炭水化物（Carbohydrate）
- **食事区分（meal type）**: 朝食 / 昼食 / 夕食 / 間食
- **目標値（goal）**: ユーザーごとに設定する1日あたりの摂取目標および体重目標
- **身体記録（body record）**: 体重・体脂肪率など日付ごとの身体データ
